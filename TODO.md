## P0

- [ ] `P0` Определить один основной backend и завершить переключение frontend на него.
  Сейчас в проекте одновременно живут два API-контура: Next.js route handlers и Django API. Frontend вызывает относительные пути `/api/catalog` и `/api/requests`, поэтому при запуске сайта запросы обслуживает Next.js SQLite-backend, а не Django. Проверка показала: Django `/api/catalog/` возвращает `meta.backend = django`, а Next `/api/catalog` обслуживается Next-приложением и этого признака не имеет.
  Готово, когда frontend читает каталог и отправляет заявки через выбранный backend, а второй API-контур удален, отключен или явно оставлен только как legacy.

- [ ] `P0` Подготовить Django settings к production.
  `manage.py check --deploy` показывает 6 предупреждений: fallback `SECRET_KEY` небезопасен, `DEBUG=True`, нет secure cookies, HSTS и SSL redirect. Также DRF Browsable API доступен при `Accept: text/html`.
  Готово, когда production без обязательных env-переменных не стартует, `DEBUG=false`, настроены `ALLOWED_HOSTS`, CORS/CSRF, secure cookies, HTTPS/HSTS за reverse proxy и выключен Browsable API вне dev.

## P1

- [ ] `P1` Починить импорт прайсов и ошибки API импорта.
  UTF-8 CSV с `;` работает, но реальные варианты ломаются: CP1251 CSV дает `UnicodeDecodeError`, CSV с запятой импортирует 0 строк, битый XLSX дает `BadZipFile`, а API `/api/imports/prices/` отвечает 500 вместо понятной 400-ошибки.
  Готово, когда импорт поддерживает UTF-8/UTF-8 BOM/CP1251, определяет разделитель, валидирует файл до записи в БД, возвращает понятные JSON-ошибки 400 и имеет тесты на плохие файлы.

- [ ] `P1` Исправить slug-и для русских марок и категорий при импорте.
  Сейчас кириллические значения схлопываются в fallback: `Шкода` и `Тойота` становятся slug `zemazap`, а `Фары` и `Бамперы` становятся `import`. В итоге разные сущности могут сливаться в одну.
  Готово, когда для кириллицы используется стабильная транслитерация или `allow_unicode=True`, а тесты подтверждают, что разные русские названия создают разные slug-и.

- [ ] `P1` Добавить строгую серверную валидацию заявок в Django.
  Django API принял заявку с `request_text` длиной 5000 символов и корзину из 75 позиций. В старом Next handler есть более строгие ограничения, но в Django они не перенесены.
  Готово, когда Django ограничивает длину полей, количество позиций, размер JSON/body, количество товара, цену и формат контакта; ошибки возвращаются как понятный JSON 400.

- [ ] `P1` Усилить антиспам для публичной формы заявок.
  Сейчас работает только общий DRF throttle примерно на 120 анонимных запросов в минуту. Для публичной формы продаж этого мало.
  Готово, когда есть отдельный throttle для `/api/requests/`, Redis/cache-backed rate limit для production, honeypot или Turnstile/CAPTCHA, логирование подозрительных попыток.

- [ ] `P1` Закрыть dependency audit по production-зависимостям frontend.
  `npm audit --omit=dev` показывает 3 advisories: `nanoid` high и `postcss` moderate через `next`.
  Готово, когда обновлены зависимости и `package-lock.json`, сборка проходит, а production audit не показывает high/moderate проблем.
